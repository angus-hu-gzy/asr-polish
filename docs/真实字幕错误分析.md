# B站 AI 字幕到底错了多少：用人工字幕当真值的实测

> 2026-11，asr-polish 0.5.6 分支。工具：`tools/eval_against_human.py`

## 一、为什么之前的数字不可信

前几轮我用的是**人造扰动**：在语料里找到「本来就写对的术语」，替换成它的变体，再回测能不能改回来。
实测召回 76.7% → 93.0%，看着不错。

但这个口径有个致命前提：**它假设错误是偶发的**（一个词偶尔写错一次，其余时候写对）。

真实 ASR 不是这样，它是**系统性偏置**——同一个词被一直写错。一篇讲 C++ 的字幕里，
`基类` 被写成 `鸡肋` 出现了 **50 次**，正确写法 `基类` 在全文里根本不出现。
文档级主题证据（「正确写法出现得够多就判定这次是错的」）因此失效。

所以必须换参照系：**找同一视频的人工字幕，逐字对照**。这是唯一不依赖我的词表、
也不依赖人造扰动的真值来源。

## 二、样本从哪来

扫了 824 个候选视频的字幕轨，**只有 13 个同时有 `ai-zh` 和人工中文轨**（`zh-CN` / `zh` / `zh-Hans`）。
人工字幕在 B 站很少见，这是样本量的硬上限。

剔除「人工与 AI 内容规模明显不成比例」的 4 个（人工只有 10 字、或 AI 篇幅是人工的两倍，
这类对齐无意义），保留 9 个 / **62,231 字**：

| 视频 | 领域 | 对照字数 | 字错率 |
|---|---|---|---|
| 20分钟学完一遍Python基础 | Python | 7,011 | 4.31% |
| 1小时学完C++ | C++ | 14,774 | 5.31% |
| 1小时学完Rust基础语法 | Rust | 17,672 | 5.75% |
| 从一家奶茶店讲透 Redis | Redis | 4,217 | 6.14% |
| 【版本管理】git 分布式版本管理 | Git | 2,857 | 6.76% |
| 当我抛弃Win11转用Linux | Linux | 5,457 | 13.05% |
| 小白第一次玩 E5 | 硬件 | 2,683 | 13.27% |
| 浙江大学翁恺教 C 语言（片段） | C 语言 | 1,304 | 14.42% |
| 全网最详细的 git 教学 | Git | 6,256 | 23.29% |
| **合计** | | **62,231** | **8.47%** |

区间很宽：4% 到 23%。**语速快、口语化、有口音、背景音的科普类明显更差**，
照着稿子讲的课程类最好。这和用户「有的视频还能看，有的完全没法看」的体感一致。

## 三、错字不是最大问题

8.47% 里有一半不是错字。按性质拆开：

| 类型 | 处数 | 占比 | 说明 |
|---|---|---|---|
| 漏句/多句 | 679 | 46% | **AI 整句丢失**，内容断裂 |
| 纯大小写 | 616 | 42% | `cout→COUT`，不影响阅读，不算错 |
| 中文同音/近音 | 528 | — | `基类→鸡肋`、`友元→有缘` |
| 英文拼错/音译 | 253 | — | `git→盖特`、`iostream→elsstream` |
| 长度不等 / 数字符号 | 283 | — | `八十→80`（AI 反而更简洁） |

去掉「纯大小写 + 数字风格」这些不算错的部分，**真实错误 1,460 处 = 2.35%**。
其中近一半（679 处）是**内容缺失**——AI 把整句吃掉了。

举一段真实例子（C++ 视频，423 秒处）：

```
人工字幕：以及通过基类引用调用派生对象的行为。
AI  字幕：以及通过鸡肋引用调用派生对象的行为
```

`基类` → `鸡肋`，在这个视频里出现 50 次。规则改不动（「鸡肋」是合法词），
懂 C++ 的人一眼就能改对。

## 四、订正器的真实覆盖率：0

13 个视频、62,231 字、1,460 处真实错误，**订正器改动 0 处**。

原因不是调参不够，是三件事同时错了：

**1. 预先枚举变体不可扩展。**
`Git` 在词表里，但 B 站把它写成「盖特」——这个词表里没有。同一术语的音译写法是**开放集合**
（Docker 可以是 多克 / 刀客 / 道克 / 达克…），词表永远收不全。实测里
`git→盖特`、`概测→盖茨` 两次都因为变体没收录而漏掉。

**2. 词表方向错了。**
真实错误主体是**中文技术术语本身的同音错**：`基类→鸡肋`、`友元→有缘`、`遍历→便利`、
`键值对→剑指队`、`计数→技术`、`多态→多肽`。而我此前收的是**英文术语的中文音译**，
两类完全是两回事。

**3. 剩下的大部分规则本来就不该碰。**
290 处中文同音错里，**170 处是单字**：`它/他`（60 次）、`作/做`（23）、`再/在`、`得/的`。
这些歧义大到人类校对标准都不统一，自动改必错。只有 84 处（多字同音）能被词表捕获，
占全部错误的 **0.2%**。

## 五、对照实验：同一段字幕，规则 0 处 vs 语言模型 CER 0%

取 C++ 视频 409~446 秒（131 字，AI 原文 CER 3.8%）：

| 版本 | 错字 | CER |
|---|---|---|
| AI 原文 | 5 | 3.8% |
| 规则订正器 | 5（**0 处改动**） | 3.8% |
| 语言模型修正 | **0** | **0.0%** |

修的四件事，规则一件都做不了：

- `通过鸡肋引用` → 通过**基类**引用（需要懂 C++ 的类继承）
- `在逐行区分` → **再**逐行区分（单字同音，且「在」在这里也说得通）
- `一份成绩和他允许` → 一**份**成绩和**它**允许（指代对象该用「它」）
- 缺 `Score`（漏内容）

## 六、还有一个更致命的：没有标点

103 万字 AI 字幕里，**中文标点共 14 处**（每 7.3 万字一个）。真实观感是这样：

```
大家好
这里是月同学期视频
我就是想用尽可能快的速度过一遍Python基础
顺便分享给身边一起学习的小伙伴们
```

平均每行 12.4 个字，一句被切成好几行，没有逗号句号。**这才是「体验感不高」的主因**，
比错字影响大得多。而这个规则同样做不了——断句需要语义理解。

## 七、结论

| 问题 | 严重度 | 规则能做 | 需要模型 |
|---|---|---|---|
| 无标点 / 断句碎 | 最高 | ✗ | ✓ |
| 整句漏失（2.35% 里的 47%） | 高 | ✗ | 部分（可检测+告警） |
| 中文技术词同音错 | 中 | 部分（多字同音，约 0.2%） | ✓ |
| 单字同音（它/他、作/做） | 中 | ✗（歧义过大，不该碰） | ✓ |
| 英文术语音译 | 中 | ✗（开放集合，枚举不可行） | ✓ |
| 英文大小写/拼写 | 低 | ✓（可做符号表校验） | 不必要 |

**纯规则路线的天花板是全部错误的 0.2%。**

三条可选方向：

- **A. 接受边界**：项目定位收窄成「高置信术语订正 + 字幕质量诊断」，主打零依赖可离线。
- **B. 分层**：核心保持零依赖（规则管能确定的），另加可选 LLM 层负责标点、同音、漏句检测。
   这是唯一能真正解决用户体感的路。
- **C. 转型成评测工具**：只做「字幕质量体检 + 真值对照」，不承诺修复。

`tools/eval_against_human.py` 无论走哪条都有用——它能在 60 秒内告诉你
「这个视频的字幕能不能看、错在哪」。
