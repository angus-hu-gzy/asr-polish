## 读到哪里，就跳到哪里

```bash
pip install -U asr-polish
asr-polish serve --port 8040
```

打开一条跑完的任务的阅读页，句子现在**点得动**了。

### 为什么改主意了

上一版的边界里写着一句「不做跳转播放器，时间戳只是让你知道这句话在第几分钟」。
当时的理由是：跳过去也只能看个大概，不如老老实实读。

真用过一遍就发现不对——读到一句拗口的，第一反应是「这人是这么说的吗」，然后就得
切回播放器，拖进度条找位置。找位置的过程比读这句话本身还长。**读和听本来是同一件事，
不该在两个窗口之间来回切。**

所以这一版把它补上了。方式仍然克制：不下载视频、不拼盗链，只用 B站官方播放器的
`bvid` / `p` / `t` 三个参数。

### 四个新东西

**① 点句子跳视频。** 点任意一句，右侧展开官方播放器，直接落在这一句的起始秒。
`t` 向下取整——62.7 秒取 62，宁可早半秒也不漏掉句头。

播放器不是一打开页面就加载的：`iframe` 初始没有 `src`，点了才建。只是读一篇文字稿，
不该先去 B站拉一个播放器。收起时把 `iframe` 置回 `about:blank`，否则声音会在后台继续放。

**② 必剪 ASR 的任务不假装能跳。** 那条路没有逐句时间，整篇是 `0 → 99:59:59` 的一整块
占位。这种任务句子不可点、不建播放器，正文上方写明原因：跳到视频开头很容易，但那是错的，
错得还不明显——用户会以为字幕对不上视频。

**③ 划重点 + 导出 md。** 鼠标移到句子上，右边露出 ☆，点一下就标上；标过的常亮，
黄底加左边一条竖条。攒了几句点「导出 md」，文件头是视频标题和 BV 号，每条带时间戳、
所属分 P、原文——直接能贴进笔记或者丢给 AI。

重点存在浏览器 `localStorage` 里，按任务 id 分组。换机器、清缓存就没了，这是有意的：
这一版不做账号、不做后端同步。

**④ 合集目录。** 多分 P 的任务左侧多一栏，列出各篇标题和段落数，点哪篇切哪篇，
搜索只算当前篇。单分 P 不显示目录，也不留一栏空白。

一个 84P 的合集如果一次全渲染出来，一屏就是几百段，所以默认只画当前篇。

### 两个显示上的错误

都是自己用的时候看出来的，一并修了：

- **右上角的统计和正文对不上。** 字数、段数原来把所有分 P 加起来：屏幕上摆着 8 段，
  角标写着「182 段」，看的人只会以为正文没加载全。现在只算当前篇，切分 P 时重算。
- **共用的 ✕ 拿不到样式。** 播放器和重点列表用的是同一个收起按钮，样式却写在
  `.player` 下面，结果重点列表那个 ✕ 渲染成浏览器默认的凸起按钮，一眼的违和。

### 没变的

- 抓取、限速、风控退避、任务状态机，一行没动。
- `GET /api/tasks/{id}/transcript` 的返回结构没动，新功能只消费它。
- 页面仍然是单个 HTML 字符串，无框架、无构建。**唯一的外部资源是官方播放器**，
  而且只在点了句子之后才加载；不点就还是断网可用。
- 服务仍然只监听 `127.0.0.1`，没有鉴权，也仍然不做账号。

### 测试

346 项（+20）。

新增的一层专门测页面里的纯函数：`tests/js/reader_logic.js` 把页面脚本灌进一个极简
DOM 桩里用 node 真跑，断言 BV 号从文件名解析得对、播放器 URL 的三个参数对、
导出的 md 里时间戳和句子没串位。只断言「HTML 里出现了 `localStorage`」证明不了算得对。
node 不在就跳过这一层，不该让没装前端工具的人跑不动测试。

带点击的流程另用真实浏览器验过：三句分别跳三个时间点、必剪 ASR 任务置灰且点不动、
标三句刷新后还在、导出 md 三条齐全、多分 P 切篇、单分 P 不显示目录。
