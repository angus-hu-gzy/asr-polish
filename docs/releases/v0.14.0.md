## 把整篇拿走

```bash
pip install -U asr-polish
```

原来只能导重点：框几句、导这几句。可你要的是整篇——丢进别的模型让它从头读一遍、
存进笔记软件、或者只是想在自己的编辑器里搜。

顶栏多了一个「导出全文 md」，和「导出重点」并排。

### 全文先做成一份东西，再说导出

这一版底下其实是个底座，导出只是顺手做掉的一层皮。

`buildFullText(transcript, task)` 吃 `transcript` 接口原样的数据，吐一份固定结构：按分 P
分组，每组带 `hasTime` / `label`，段落是 `{start, end, text}`。以后总结、问答、测验、
合集检索，凡是要「全文」的都调它，不要各自去遍历 `segments`。

同一个任务，两处各写一遍「全文是什么」，迟早会不一样——一处改了分 P 的边界，另一处还
按老的算，用户看到的是两个版本的字幕，而没有任何界面提示他这件事。

配套两个出口，都只消费这一份结构：`buildPlainText(full)` 给模型（一行一段，分 P 之间一条
`---`，不带时间），`buildFullMarkdown(full, now, task)` 给人看。

### 三个判断

**分段复用屏幕上那套。** 导出的段落必须和页面上看到的一致。换一套算法，用户第一反应是
「导错了」，不会想到「分段算法本来就不同」。

**占位时间一律变 `null`。** 必剪 ASR 和纯 txt 这两条路，`srt` 里整篇是 `0 → 99:59:59`
一整块。`99:59:59` 比没有时间更糟：下游会当成真的引用。也绝不把总时长平均摊成几百个
时间戳——那是编数据。

**没有时间戳的篇，写清楚为什么。** 每段标 `[无时间戳]`，节首加一句「这一篇没有逐句时间
戳……这是标注，不是真实时间」。留白会被当成解析失败，读者只会以为工具坏了。

### 顺手收拾的两处

- **下载逻辑只留一份。** 抽了 `saveBlob()`，重点导出和全文导出共用同一个 `Blob` +
  `a[download]`。两套会各自改一半 `revokeObjectURL` 的时机和文件名转义，而这只在用户下到
  一个空文件的时候才暴露。
- **按钮放顶栏，不塞进重点面板。** 重点面板默认收起，塞进去等于要先点开重点才能导全文，
  可这两件事没关系。

### 没有产出的任务

导出按钮置灰，回调里也先判 `parts` 为空就返回——两层。空文档上不会下出一个只有文件头的
md。

### 没变的

- 抓取、限速、风控退避、状态机、`transcript` 接口结构一行没动。
- 搜索、划重点、播放器、合集目录、断点续读、夜间模式，行为全不变。**导出重点逐字节一致**：
  同一个夹具跑改动前后的页面脚本，三份 md 输出、文件名、链接全部相同，md5 相同。
- 页面仍是 `reader.py` 生成的单文件 HTML，无框架、无构建步骤、核心零依赖。
- 仍然只监听 `127.0.0.1`，没有账号、不做跨设备同步。

### 测试

407 项（+15）。全文组装、纯文本出口、md 组装（时间戳 / 无时间戳 / 多分 P 标题 / 文件名）
全做成能进 node 单测的纯函数。结构上还钉了一条：`exportFull` 的回调里不许再出现
`segments`——出口只准消费 `buildFullText` 的结果。

真浏览器 33 项：多分 P 导出 182 行逐行与页面比对（时间戳和正文全中）、必剪 ASR 每段
`[无时间戳]` 且全文找不到 `99:59:59`、空任务按钮不可用且点了不落文件、单篇不带「P1」、
工具栏不换行、搜索 / 点句跳视频 / 断点续读各走一遍、无 JS 异常。
