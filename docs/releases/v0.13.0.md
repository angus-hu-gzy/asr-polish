## 阅读页能关灯了

```bash
pip install -U asr-polish
```

晚上读长文，暖白底整屏晃眼。顶栏加了一个按钮，白天 / 夜间来回切。

选过就记住，下次打开还是那个；没选过则跟随系统——系统是深色就直接进夜间，不用手动点。

### 颜色是收进变量做的，不是逐个改

样式表里原来有 48 个散落的硬编码颜色。这次全部归成 30 多个语义变量：`--paper` /
`--panel` / `--field` 三层表面，`--ink` / `--muted` / `--faint` 三档字色，加命中色和
语义色。夜间只覆盖一组值，规则里一个色值都不留。

逐元素改颜色是做不到「不漏一块」的。漏掉的那处就是深底上的一张白卡片——比整个没做夜间
还显眼。测试里钉了这一条：`:root` 两块之外不许出现任何色值，播放器框的 `#000` 除外
（黑边两套都该黑）。

### 夜间不是纯黑配纯白

底是深暖灰 `#17150f`，正文 `#d8d2c4`。对比太硬看着累。

三档字色、三层表面的层级关系和白天一致，谁亮谁暗没有颠倒：纸面最沉、面板浮一档、输入
框再亮一档；字反过来，正文最亮、时间戳最暗。唯一往上提的是夜间的时间戳——对比度 4.9:1，
比白天的 2.4:1 还高一点。它是用来定位句子的，压太暗就白搭了。

### 命中色在夜间要反过来

普通命中是压暗的琥珀块配浅黄字（暗块亮字），当前那一处反过来用亮琥珀配深字（亮块暗字）。
同一色系的深浅两个方向，扫一眼就分得开。

直接沿用白天的 `#ffe98a` 不行：深底上那一块黄会把句子吃掉。重点段左侧的竖条保留。

### 一个容易踩的时序问题

主题必须在 `<head>` 里定，早于 `<style>`。

放到页面末尾那段脚本里会晚一帧——夜间用户每次刷新，都会先看到一下白底再变暗。这正是
这个功能要解决的那一下，为了省事放进末尾等于没做。代价是键名要在两处各写一遍（跨
`<script>` 共享不了常量），测试钉住两处一致。

### 没变的

- **白天模式和 0.12.2 逐像素一致。** 把 `reader.py` 退回上一版、另起一个端口跑同一份
  截图脚本再逐像素比对：表头以下 0 个像素不同。
- **切换只改颜色，不改布局。** 表头、搜索条、正文、段落、目录、按钮六个盒子，切前切后
  尺寸位置完全一致。
- 搜索、划重点、导出 md、合集目录、断点续读、点句子跳视频，行为全不变。
- 任务面板 `app.py` 没动（这功能只属于 `/reader`）。抓取、限速、风控退避、任务状态机、
  `transcript` 接口一行没动。
- 页面仍是 `reader.py` 生成的单文件 HTML，无框架、无构建步骤、核心零依赖。仍只监听
  `127.0.0.1`，没有账号、不做跨设备同步。

### 测试

392 项（+12）。新增的是能真正拦住回归的结构断言：色值不许硬编码、夜间必须覆盖白天每
一个变量、引导脚本必须排在 `<style>` 之前；纯函数层加了 `themeFrom` / `nextTheme` /
`themeLabel`。

真浏览器另验 43 项：两套模式逐面比色、全页扫浅色块（夜间 0 处）、切模式前后布局逐元素
比对、两种命中互不混淆、刷新各自保持、清空后跟随系统且不写死、点句子照常起播放器、
无 JS 异常。夜间首帧亮度 20.6，白天首帧 240.1——对照证明这个测法抓得到白，夜间那次首帧
就已经是暗的。
