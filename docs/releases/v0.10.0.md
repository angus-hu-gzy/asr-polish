## 说一句话就能取字幕了

```bash
pip install -U asr-polish
```

装完得到两个命令：`asr-polish`（命令行）和 **`asr-polish-mcp`**（MCP server）。

这个版本只做一件事：**把取字幕这件事从「记得命令」变成「说一句话」。**

### 为什么

装完之后的使用姿势是——打开终端、回忆命令、敲对参数、再去目录里翻文件。
但真实场景里人是这么说话的：**「帮我把这条视频的字幕取下来，顺手订正一下」**。
中间那一层没有产生任何价值。

所以把同一个 `run_subs` 包成 MCP 工具。**没有新增任何抓取逻辑**：
`complete` / `partial` / `empty` / `failed` 四态、失败明细、「只重跑失败条目」
的行为，跟 CLI 和服务端**是同一份实现**，不是另写一遍。

### 四个工具

| 工具 | 干什么 |
|---|---|
| `fetch_subtitles` | 取字幕落盘。`target` 支持 BV 号 / `up:` / `season:` / `search:` |
| `list_videos` | 只列清单不下载——先看看有什么再决定抓哪些 |
| `correct_text` | 术语订正，不联网、不改文件 |
| `check_login` | 真请求一次 `nav` 接口验证 Cookie |

客户端配置：

```json
{
  "mcpServers": {
    "asr-polish": { "command": "asr-polish-mcp" }
  }
}
```

### 一个实测出来的坑

第一次跑通之后随手拿一个真实合集试了试，是个 **84 P 的课程**。
在调用方眼里它是「一条视频」，于是：84 次请求、166 个文件、几万字节的返回体。

所以加了单视频分P上限（默认 20）。**不静默截断**——返回里会说
「共 84 P 只取了 3 个，要全取传 `max_parts: 0`」。批量的正路仍然是
`asr-polish serve`（有队列、断点、面板）。

### 顺手修掉一个死字段

`BiliRiskControl.retry_after` 从 0.6 起就在，赋过值、**从来没被读过**——
退避永远按硬编码的 60/180/300 走。现在 412/429 会真的解析响应头
（秒数与 HTTP 日期两种写法都认），夹在 30~600 秒：

- 对方说等 30 秒 → 等 30 秒，不是 60
- 对方说等 0 秒 → 还是等 30 秒（刚被拦立刻再打，判定只会更重）
- 对方说一小时后 → **直接失败并说清原因**，而不是 300 秒后继续撞三次

没有这个头时（大多数情况，风控走业务码不走 HTTP 状态）回落到原来的固定档位。

### 测试

301 项（+37）。其中一条 CI 替我抓出来的：退避用例原本假设 `-352` 一定走退避，
但开发机有 Cookie → 判成「太快」，CI 上没有 Cookie → 判成「没登录」直接抛——
**同一份测试两边结论不同**。代码是对的，测试的假设错了，现在把分类那一步钉住，
另外补一条用例正面锁住「未登录时一秒都不等」。

本地复验方式：`USERPROFILE` 指到空目录模拟无 Cookie，301 项在两种环境下都过。
