阅读页能就当前这一篇提问了。回答里的每条事实都要带一处原文时间，而那些时间会被拿真实的
段首再核一遍——对得上的才能点。

## 一个例子

读到第三十分钟，字幕里冒出一串没听过的参数，前面讲过没有、讲过多少，翻回去找很烦。

顶栏点「问答」，面板开在正文里，不挡字。问「这几个参数分别在什么时候提到的」：

> 提到三次。第一次在 `[28:14]` 介绍用途，第二次在 `[31:02]` 对比阈值，第三次在
> `[33:20]` 说「上面那两组数据」——这一段没有重复参数名，指的是前一次。

三个方括号都是锚点。点 `[31:02]`，滚到那一段、闪一下；再点一次，视频跳到 31 分 02 秒。
想读正文的时候不该被拽去播放器，所以一次点击只干一件事。

## 出处不是模型说了算

这一层最容易做假的地方就在这儿：模型很会写时间，写出来还都像模像样。

所以正文发过去之前，一行一段补上 `[mm:ss]`，要求它引用时从里面抄，不许自己算。抄回来的
时间再拿**真实段首**比一遍，容差 1.5 秒。

为什么是 1.5 秒而不是 0：页面显示的时间是四舍五入的（`start` 62.7 显示成 `01:03`），严格
相等会让每条都被判成无出处。为什么不是 5 秒：会指到隔壁那段去。相邻段间隔普遍大于 2 秒，
取最近一段不会跳错。

对不上的灰着、点不动。一条都对不上，就在回答下面补一句「本次回答没有可验证的出处，仅供参考」
——不是拒绝显示，是不让它装作有据。

顺带一个副作用值得说：**编出来的引用过不了这道核对**。模型想编 `[45:12]`，得正好编到某个
真实段首的 ±1.5 秒内，这个概率低到可以当作不存在。

## 「原文中没有提到」是一句要写进提示词的话

不问它会不会编，而是先给它一条出路。提示词里三条规则写死在服务端常量里：

1. 只能依据提供的正文；
2. 每条事实必须引用原文出现过的时间；
3. 原文没有的，直接写「原文中没有提到」。

第三条是关键。只写前两条，模型遇到答不上来的问题会**绕着编**——用正文里的词拼一个看似合理
的答案，再配一个像样的时间。给了它一句可以直说的话，它就不必编。

## 必剪 ASR 的篇：能问，但不定位

有些视频没有字幕轨，走的是必剪云端 ASR。那种结果只有整段文字，没有逐句时间轴。

这一层照常能问，只是不产生锚点，面板顶上常驻一句「这一篇没有逐句时间戳，回答无法定位到
视频」。

**没有画灰字「无出处」。** 试过，满屏灰字的第一反应是「这工具不准」，而不是「这篇没有时间
轴」。改成方括号原样留着，原因写在顶上——不知道原因，功能看起来就是坏的。

## 花钱这件事，写在输入框旁边

问答和总结一样，用你自己填的模型。所以：

- 每问一次就是一次模型调用，输入框旁边常驻一行，不藏在帮助文档里；
- 只把最近 6 轮历史带过去（前端裁一次、服务端再裁一次）。历史每轮都重发全文的话，问到第六
  句时 token 里躺着六份正文，全是重复计费。更早的对话留在页面上，只是不再发出去；
- 没配好之前按钮上写「先配模型」，输入框那一行直接写缺什么（缺服务地址、模型名、API key），
  不用停鼠标看提示。

对话存在浏览器里，按「任务 + 分 P」分组：刷新还在、切篇各看各的、「清空对话」只清当前这一篇。
任务重跑、字幕变了，旧对话按与第 1 层总结同一个指纹作废——拿着旧对话配新字幕，比没有对话
更糟。

## 与任务书不一致的两处

**一、正文对齐在前端做，不在服务端。** 任务书写的是「服务端按行对齐回 `buildFullText` 结构、
行首补 `[mm:ss]`」。实际做法是前端拼好（`buildSummarySource` 本来就干这件事）、服务端只转发。

理由：对齐要拿到 transcript，而服务端手上只有前端发来的那段纯文本。让它重新对齐，等于把同一
套「行数对不对得上、对不上就整篇不标」的逻辑写第二遍，还要再把 transcript 传一遍。同一件事
有两个实现，早晚会不一致。

**二、只带 6 轮，不带全部。** 这条任务书里就有，这里写出来是因为它影响能力：问第七轮时，
第一轮说的话模型已经看不见了。页面没删，只是不发。

## 顺手修掉的八个坑

这一版还把「跑久了 / 跑批了 / 跑错了」的一批问题清了。共同点是**都不报错，或者报一个指向
错误方向的错**：

每个 HTTP 请求泄漏一条 SQLite 连接（面板轮询一小时一千多条，Linux 上撞 `ulimit` 之后所有
API 一起报 `unable to open database file`，看起来像服务挂了但进程还在）；必剪 ASR 那一段
（下载 + 上传 + 轮询云端，最多 25 分钟）没有心跳，回收器按 600 秒判僵尸，正常的长视频会被
重新下载三轮后变成 failed，错误写着「心跳超时」；wbi 的 `mixin_key` 缓存永不过期，常驻跨过
轮换点之后每个请求都用旧密钥签名，B站一律回风控，而提示让用户「把 `--min-interval` 调大」
——真该做的是重取密钥；必剪链路的异常不是 `BiliError`，漏出去一个就吃掉整批已抓到的条目；
`--pages 5` 打在只有 3 个分 P 的视频上，零产出被报成「全部成功」，退出码 0；`/api/tasks`
不校验字段类型，`target` 传成数字会让面板每 3 秒 reject 一次、列表永久停在上一帧；`--cookie`
给了不存在的路径会静默改用别的文件（「我明明换了 Cookie 还是 -352」）；切任务时上一轮在途的
请求会写进新页面，甚至让「点句子」打开上一个视频。

还有一条不是用户的坑但会咬到贡献者：CI 闸门会漏判「刚推上去的提交」——`head_sha=` 走
GitHub 的索引，push 完那几十秒返回空，判成「查不到」。现在查空时退化成拉一页本地挑。

## 没变的

- 抓取、限速、风控退避、状态机、`transcript` 接口结构一行没动。
- `buildFullText` / `buildPlainText` / `buildFullMarkdown` / `buildSummarySource` 的逻辑一行
  没动。
- 划重点、搜索、播放器、合集目录、断点续读、夜间模式、导出、单篇总结，行为全不变。
- 页面仍是单文件 HTML，无框架、无构建步骤；仍然只监听 `127.0.0.1`，没有账号，对话不落后端。
- key 仍然只在浏览器里，随请求发给本机服务转发，不落盘、不进日志。

## 测试

548 项（+75），真浏览器 35 项。

后端 `test_qa.py` 18 项里有一条是「正文在一次请求里只出现一次」——真起一个假模型服务，把请求
收下来数 `messages` 里正文出现了几遍。这条盯的是钱。另有「key 不出现在任何错误消息里」
（`assertNotIn`），两次提问必须是两次真实调用，第二次请求必须带上一轮。

浏览器里跑的是端到端：点示例问题真问一次、两个真引用成锚点而编造的 `59:59` 灰着、点锚点段落
闪、再点跳视频 `t=5`、问原文没有的得到「原文中没有提到」且不给引用、刷新对话还在、第二篇是
另一份对话、清空只清当前篇、没配 key 时按钮变「先配模型」、填错 key 带出提供方原话与下一步。

还有一件事：**源码包自己跑不过自己的测试**，这一版才发现，也就没有跟着发出去。测试里有一项
去核对 `.gitattributes` 钉住钩子换行，而 `.gitattributes` 没进 `MANIFEST.in`——解包、`pytest`，
`FileNotFoundError` 红一项。0.15.1 漏掉 `tests/js/reader_logic.js` 时红了 51 项，同一个坑第
二次。现在补进包，CI 的 `build` job 也多一步：解包 sdist、在包里跑一遍 pytest。文件清单对不对，
`tar tzf` 数不出来。
