前三层都在服务「这一次阅读」：总结、问答、测验，关了页面就散在浏览器里。这一层把看完的

## 一个例子

一篇讲本地字幕工作流的视频，读完点顶栏「笔记」→「存入笔记库」。目录里多出这些：

```
notes/
  INDEX.md              目录：先视频、后概念
  在本地跑起一套字幕工作流 · P1.md
  concepts/阈值.md
  concepts/限流.md
```

视频笔记打开是这样：

```markdown
---
标题: "在本地跑起一套字幕工作流"
BV号: "BV1xx411c7mD"
分P: "P1"
日期: "2026-11-07"
来源任务: "T5f2a91c0"
生成时间: "2026-11-07 13:26"
分P序号: "0"
指纹: "5:115:大家好，这一期我们聊聊怎么在本|最后一步是把脚本放在同一个目录下再运行"
分P文件: "BV1xx411c7mD-P1-在本地跑起一套字幕工作流.srt"
模型: "qwen-plus"
---

# 在本地跑起一套字幕工作流

## 要点

- 先把 srt 和 txt 两种格式都抓下来，后面补时间轴不用重跑 [00:12](http://127.0.0.1:8040/reader?task=T5f2a91c0&part=0&t=12)
- 阈值调到 0.7 之后，误报明显少了 [12:41](http://127.0.0.1:8040/reader?task=T5f2a91c0&part=0&t=761)

## 概念

- [[阈值]] — 触发判定的那条界线，超过就报。 [12:41](http://127.0.0.1:8040/reader?task=T5f2a91c0&part=0&t=761)
- [[限流]] — 单位时间里只放行固定数量的请求。 [00:12](http://127.0.0.1:8040/reader?task=T5f2a91c0&part=0&t=12)
```

概念笔记是另一份，讲的是「这个概念是什么」而不是「这一篇怎么讲」：

```markdown
---
概念: "阈值"
首次出现: "2026-11-07"
---

# 阈值

触发判定的那条界线，超过就报。

## 出现过的地方

- [在本地跑起一套字幕工作流 · P1](http://127.0.0.1:8040/reader?task=T5f2a91c0&part=0) · [12:41](http://127.0.0.1:8040/reader?task=T5f2a91c0&part=0&t=761)
- [另一篇也讲到了 · P3](http://127.0.0.1:8040/reader?task=T9a71cd02&part=2) · [03:08](http://127.0.0.1:8040/reader?task=T9a71cd02&part=2&t=188)
```

`[[阈值]]` 是 wikilink，Obsidian 里点得过去；锚点也能点，回到阅读页那一段并闪一下。同一个
概念在第二篇里再出现，只会往「出现过的地方」多一行，不会新建文件。

## 库是文件，不是又一个 localStorage

这是这一层唯一想清楚才动手的地方。前三个结果都可以只活在浏览器里——它们服务的是「正在读
的这一篇」，关掉就不再需要。笔记不一样：它要跨篇攒起来，要能被 Obsidian 打开、被 grep、
被 git 管版本。那就只能落盘，而且必须是**人可读的 md**，不能是 json。

目录没另起一套，直接沿用 `FOR_AI.md` 里已经写下的约定（`notes/` + `INDEX.md`）。在那份约定
里，这个目录本来就可以由人写、由人改；现在只是多了一个自动写的入口。所以：`INDEX.md` 每次
从磁盘重建（人删了文件，目录跟着消失），`<标题>.md` 和 `concepts/*.md` 可以手改——手加的行
读不回来时跳过，不会让整页崩。

写入走「临时文件 + `os.replace`」，Windows 上 Obsidian 或杀软占着文件时 `PermissionError`
会退避重试，不会留下半截 md。文件名走 `export.safe_name`，和导出 md 同一套规则。

## 概念要复用，所以把已有的名字喂回去

这一层最容易做假的地方是去重。

模型每次都会给同一个概念换个叫法：「阈值」「判定阈值」「阈值线」。如果不管，库里的概念文件
会一篇涨三个，一年后是一个你不敢打开的目录。所以每次调用都把**库里已有的概念名**塞进提示
词，要求原样复用——只给名字，不给正文：给了正文，模型会开始抄定义，抄着抄着就把两篇的说法
揉成一句没人说过的话。

归一只做四件事：NFKC、去首尾空白、折叠中间空白、ASCII 小写。认的是「同一个字符串的两种
写法」。近义合并、繁简转换一概不做。

这个取舍是偏保守的，代价明确：库里会多几个本该合并的文件。反过来，焊错了是不可逆的——
两个概念被并成一个之后，用户看不出是哪一步焊的，也不知道原来分开过。多一个文件只是多一个
文件，少一个概念却是丢了一样东西。

概念笔记的定义只留第一次那一份。同一个概念在不同视频里的说法会飘，每次覆盖会让文件变成
「最后一篇怎么讲」，而不是「这个概念是什么」。

## 出处对不上就不写时间

模型抄行首的 `[分:秒]`，服务端拿这一篇**真实的段首**核一遍，容差 1.5 秒。对得上的写成可点
锚点；对不上的**一个时间字符都不写**，只留文字。

写进文件的时间用的是真实段首，不是模型给的数字。模型给 `01:23`，那一段实际从 82.6 秒起，
文件里写 `[01:23]` 指向 83——点进去落在那一段上，读的人才不会觉得「差了几秒」。

编一个时间进去比不写坏得多：文件会被读很多次，而读的人无法分辨哪条是原文讲过的。

## 没时间的篇照常写，但一条锚点都不给

必剪 ASR 那种没有逐句时间戳的篇，笔记照常写——要点、概念都在，只是概念不出时间锚点，
文件顶上写明：

> 这一篇没有逐句时间戳，概念无法定位到视频。

试过画满屏灰字，第一反应是「这工具不准」，而不是「这篇没有时间轴」。不如把话说在前面。

## 残缺的概念不写，并且说清缺什么

没有定义、名字为空、该有出处却没有的概念，一律在服务端拦下，理由带回前端：

> 有 1 条没写进去：概念「没有定义的概念」没有定义

能用的照常写。一条都用不了才整体报错。不说的话，用户会以为模型只找出两个概念。

## 来源变了要说

frontmatter 记了来源任务 id、生成时间和这一篇的指纹（段数 + 总字数 + 首尾 24 字）。

任务重跑、字幕变了之后指纹对不上，`/notes` 顶上写「有 1 篇笔记的来源字幕变过了」，卡片上
挂一枚黄标「来源已更新，建议重新生成」。规则和总结缓存、问答记录、测验记录是同一个——同一
件事不该有第二套判据。

## `/notes` 只渲染生成器写得出的结构

`/notes` 是搜得到、点得回去的一页：不搜时按日期倒序列全部，搜的时候做关键词匹配（标题、
BV 号、正文、概念名、定义），命中原因写在卡片上。

搜索故意只做字符串包含，不做语义检索——搜什么就命中什么，用户能预测。

页面只渲染生成器写出来的那几种固定结构：`##` 小标题、`-` 列表、`[[链接]]`、出处锚点、
`>` 说明行。不为它写通用 Markdown 渲染器：结构本来是固定的，写一个渲染器要处理标题层级、
代码块、表格、转义，每一处都能出错，换来的只是「万一用户手改了一行也能显示」。

## 实测里改掉的四处

- **没有锚点的出处会在重写时被吃掉。** 概念笔记是「读出来 → 追加一行 → 整篇写回」，而读回
  那一步原先要求每行都带 `t=`：必剪那一篇的出处没有时间，读不回来，重写时就被抹掉。结果
  是库里的出处随着保存次数一次次变少，而且看不出是谁删的。现在出处行本身就是链接（标题链
  到那一篇），`t` 可有可无。
- **同一篇里同一个概念写两行出处。** 去重的键从「任务 + 分P + 秒」改成「任务 + 分P」：出处
  的最小单位是这一篇，按秒去重会让同一篇列出好几行，读的人以为它出现在好几个视频里。视频
  笔记的 `## 概念` 也按名字归并，界面上「N 个概念」这才和文件里一致（之前会说 3 个，文件
  里只有 2 个）。
- **多分 P 的「分P序号」恒为 0。** 写的是 `index`、读的是 `part_index`，锚点会指到第 1 篇的
  同一秒上。
- **列表按文件名排，不是按日期。** 文件系统顺序是码位顺序（`带时间` 排在 `必剪` 前面），和
  人想要的顺序无关：新的该在上。

顺带补了两处：`/api/notes/search?q=` 问空串时返回全部（空查询等价于「不搜」，接口自己站得
住），`INDEX.md` 和页面共用同一个排序函数（各排各的，早晚不一致）。

## 与任务书不一致的两处

**一、顶栏入口叫「笔记」，不是「存入笔记库」。** `存入笔记库` 是面板里那个按钮。理由是
「写到哪个文件、新建几个概念、复用几个、坏了几条」得有地方显示，而前三层（总结 / 问答 /
测验）都是这个形状：顶栏一个入口，面板里一次付费动作，价格说明常驻。一次点击仍然只对应
一次模型调用。

**二、没有照抄 `summary.parse_content`。** 这一层的输出是 points + concepts，和摘要的形状
不同，硬套只会多一层转译。复用到底的是 `require_cfg` → `complete` → 错误翻译那条链，以及
`json_object` 与时间戳解析——没有第二份调模型代码。

## 没变的

- 抓取、限速、风控退避、状态机、`transcript` 接口结构一行没动。
- `buildFullText` / `buildPlainText` / `buildFullMarkdown` / `buildSummarySource` /
  `buildModelSource` 的逻辑一行没动。喂给模型的正文仍然由前端拼好（含行首 `[mm:ss]`），
  服务端只转发、只多读一次磁盘——锚点要用真实段首核，指纹要拿它算。
- 划重点、搜索、播放器、合集目录、断点续读、夜间模式、导出、总结、问答、测验，行为全不变。
- 页面仍是单文件 HTML，无框架、无构建；仍只监听 `127.0.0.1`，没有账号，笔记不落后端。
- key 仍然只在浏览器里，随请求发到本机服务转发，不落盘、不进日志。

## 测试

**693 项（+72）**，`ruff --select F,E9` 干净。

`test_notes.py` 盯的是这一层会出错的地方：提示词里那几条规定都在、概念归一的边界（全角、
空格、大小写各一条，近义与繁简**不该**合并）、第二个视频只追加不新建、缺定义的概念被拦下
且理由对得上、frontmatter 的每个字段、`INDEX.md` 的两段结构、检索的命中原因、指纹对不上时
的过期标记。写文件全部落在临时目录里，不碰仓库。

`notes_page.py` 的渲染函数是纯函数，在 node 里带夹具跑（和 `tests/js/reader_logic.js` 一个
套路）：列表渲染、过期徽标、锚点标签、空库、搜索高亮原因。

浏览器里跑的是端到端：两分 P 的演示库 + 一个故意的假模型（给了一个编的 `59:59`、一个缺定义
的概念、一个带空格的同名概念）——编的时间只留文字不写锚点；缺定义的被拦下并在界面说明；
带空格的归一到同一个文件、复用而不是新建；第二个视频只给已有概念追加一行；锚点跳回原文落
点实测 `t=30` → 第 2 段闪一下；人为改掉指纹后 `/notes` 顶上报过期、卡片挂黄标；没配模型时
顶栏按钮变「先配模型」，点一下直接开设置面板。全程无 JS 报错。

## 升级

从 0.17.0 升上来没有要迁移的东西。`serve` 默认写到当前目录的 `notes/`，要换位置用
`--notes-dir`。这个目录已经进了 `.gitignore`（和 `subs/` 一个性质：里面是别人视频的正文），
但如果你想把笔记当知识库管版本，把它从忽略里去掉、单独 git init 都行——它就是一堆 md。
