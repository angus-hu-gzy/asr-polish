## v0.8.0 — 批量抓不会再把账号抓进风控

**只用单个 BV 号抓过几条的话，这一版没有必须升级的理由。** 一旦开始抓 `up:` 或 `season:` 的几十上百条，它很关键。

### 这一版解决的问题

之前抓一个 UP 主的全部投稿，是几百个请求连着打出去，中间没有任何间隔。B站的反应是 `-352 风控校验失败`。

旧代码把这个和「这条视频取不到」当成同一类事：记一条失败，接着打下一条。问题是**下一个请求本身就是风控的燃料**——越失败越打，越打越失败，正好帮对方把封禁续上。

现在分三层处理：

**① 主动限速。** 同一域名的目标请求间隔是 **1 秒，带 ±30% 抖动**——实际在 0.7～1.3 秒之间无规律波动。固定 1000 毫秒的等间隔本身就是机器特征，抖动是为了不让自己长得像脚本。

节流放在 `_http_json` 底层，不是批量循环里。循环里加 `sleep` 只能管主流程，管不到翻页、wbi 密钥这些旁路请求——风控照样会来。只节流 `api.bilibili.com`：必剪的轮询本来就该 1 秒一次，字幕 CDN 是静态资源，拖慢它们换不来任何风控上的好处。

**② 撞上也退避。** 识别 `-352 / -412 / -799 / -509` 和 HTTP `412 / 429`，遇到就 **60 → 180 → 300 秒**退避后重试**同一条**，累计 9 分钟仍被拦才判失败，错误信息直接给可操作建议。

这里有个不处理就会悄悄出错的细节：退避 300 秒期间如果不刷心跳，僵尸回收器会把这个任务当成卡死、放回队列重跑。所以退避被切成 15 秒一段，每段刷新心跳，面板上能直接看到「退避 180s，还需 60s」。

**③ 先分清原因再动手。** 「没登录」和「请求太快」返回码都是 `-352`，但处置正好相反：前者要换 Cookie，后者等一下就好。遇到 `-352` 会先用 `nav` 探一次登录态（缓存 5 分钟，且跟着 Cookie 文件的修改时间走），未登录就直接报「需要登录态」，不再白等 9 分钟。

实测：未登录时抓 `up:` 是 **4.5 秒失败并说明原因**，而不是等到 9 分钟后只报一句「风控」。

### 新增 `asr-polish cookie`

开发这一版的过程中碰到一个真实故障，正好说明为什么需要它：

> 一份 `cookies.txt` 里 SESSDATA **还剩 176 天没过期**，`nav` 接口却返回 `-101 账号未登录`。

也就是说，SESSDATA 被**服务端注销**了（改密码、被踢下线、长期不用）。文件看着完全正常，只看过期时间永远发现不了。

所以判断依据改成 `nav` 接口的 `isLogin`，`/api/health` 默认带上这个结论，面板顶部横幅按绿 / 黄 / 红上色。同时给了更省事的做法——不用装浏览器插件，也不用自己拼 Netscape 格式：

1. 打开 bilibili.com，确认右上角是自己的头像；
2. `F12` → **网络 / Network** → `F5` 刷新；
3. 点第一条请求 → **请求标头** → 找到 `cookie:` 那行，右键 **复制值**。

```bash
asr-polish cookie        # 查看状态（联网确认 isLogin）
asr-polish cookie set    # 直接读剪贴板，写完立刻验证
```

写入是**合并**而不是覆盖：只更新同名的那几条，`buvid3` 这类设备指纹保留。只贴了 SESSDATA 就整份覆盖，会顺手把设备指纹抹掉，反而更容易被风控。缺 SESSDATA 的内容直接拒绝——那是「未登录」状态的 Cookie，写进去只会让人以为配好了。

写文件走「临时文件 → 验证能读回 → 原子替换」，粘贴内容有问题时原文件不受影响。

### 修复

- **取字幕时每条视频都重复请求一次 `nav`**，明明有进程内缓存却没用。抓 50 条就是 50 个多余请求，纯属给风控递理由。每条视频的 API 请求从 4 个降到 3 个。
- **wbi 密钥长度未校验** —— 密钥短于 64 字符时 `raw[i]` 直接 `IndexError`。现在明确报「wbi 密钥长度异常，接口可能已变更」。
- **`Store.close()` 只关当前线程的连接。** worker 线程退出后它的连接没人关，在 Windows 上会锁住库文件（实测泄漏 11 个）。现在维护连接全集统一关闭，并给连接加 `check_same_thread=False`——否则跨线程关闭会被 SQLite 直接拒绝，`except` 一吞就永远查不出来。
- **`#HttpOnly_` 开头的 SESSDATA 被当成注释。** 浏览器插件导出的 cookies.txt 会给 HttpOnly 项加这个前缀，原来的文本扫描直接跳过 `#` 开头的行，于是有效 Cookie 被判成「文件里没有 SESSDATA」。
- **重试后成功的任务保留着上一次的 error**，面板上「完成」的任务底下挂着红字，看的人只会以为它失败了。
- **未登录时「无字幕」的结论不准。** AI 字幕（`ai-zh`）需要登录才下发，未登录时「取不到字幕」和「这视频本来没字幕」长得一模一样。现在会追加 warning 并写进任务结果（`items[].note`）。

### 代价

**批量抓比以前慢：每条视频 3 个请求 × 1 秒间隔。** 这是刻意的取舍——「不被封」优先于「快」。嫌慢可以 `--min-interval 0.5`，但别低于这个数。

`subs -j` 的并发数从此不再影响 API 压力，只影响音频下载与本地处理。

**没有新增任何数据源，也没有改抓取能力。** 字幕解析、必剪 ASR 兜底、播放地址获取这些逻辑本身没有变化——`bili.py` 那 400 多行改的全是错误识别、登录态判断和旁路请求的优化。这一版增加的不是「能抓到什么」，而是「怎么跑才不会把自己跑死」。

### 测试

117 → 192 项。新增覆盖：节流间隔与并发不重叠、风控码识别、退避序列与心跳、Cookie 三态与登录探测缓存、Cookie 导入的解析 / 合并 / 拒绝 / 原子写入、重试后清 error、连接泄漏。

### 安装

```bash
pip install git+https://github.com/angus-hu-gzy/asr-polish.git@v0.8.0
```

从 0.7.x 升级不用改任何调用方式。新增 `--min-interval` 参数（`subs` 与 `serve` 都有），默认 1.0。
