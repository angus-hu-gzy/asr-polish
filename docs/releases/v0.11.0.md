## 抓完之后，终于能读了

```bash
pip install -U asr-polish
asr-polish serve --port 8040
```

打开 `http://127.0.0.1:8040`，跑完的任务后面会多一个 **「阅读 →」**。

### 为什么

前几版一直在解决「怎么把字幕弄下来」：批量、限速、断点、风控退避、四态、只重跑失败的
几条。但字幕落盘之后是一堆 `BV1xx-标题.srt`，想看一眼讲了什么，还得打开播放器拖进度条
——**抓取已经自动化了，阅读没有**。

这一版补的就是这一步：把同一份字幕排成一篇**能顺着读下去**的文字稿。

### 它长什么样

左边时间戳、右边正文，一段一段往下读；顶部一条搜索框，输入关键词当场黄底高亮，
回车跳到下一处，段落会滚到屏幕中间闪一下。搜「注意力」就能直接跳到讲它的那句话。

- **按时间轴分段**，不是一句一行。B站 AI 字幕一条只有十来个字，一句被切成好几行，
  逐条画出来仍然是碎的——只是每行前面多了个时间戳。
- **四态照旧**：全部成功 / 部分成功 / 没有产出 / 全部失败，徽章在页面顶部，失败明细在
  页面底部，还能「只重跑这 N 条」。
- **出错时说清是哪一种**：没字幕 ≠ 出错。无字幕会告诉你「B站上并非每个视频都有字幕，
  要转写音频得用 `--asr` 走必剪 ASR」；被风控会告诉你「不是代码问题，等几分钟或者把
  请求间隔调大」；Cookie 失效直接给三步操作。

### 三个被真实数据逼出来的判断

**① srt 不能按空行切块。** 手工写的解析器都从「按空行分块」开始，然后在 Windows 上
翻车：CRLF 文本被文本模式再写一遍会变成 `\r\r\n`，多出一个空行，序号 / 时间轴 / 正文
被拆进三个块，整篇解析成 0 段——页面一片空白，看起来像接口挂了。现在按 `-->` 扫行，
先把连续 `\r` 折成一个；坏块只跳过自己。

**② 时间轴断不了句。** 本来想用「间隔大于 0.8 秒就换段」，实测这批数据的行间隔中位数
是 **0.00s**——字幕轨本来就是首尾相接排的，停顿根本不在里面。只靠长度上限的结果是：
58 条字幕变成 3 段、每段 200 字，读起来像三块砖。最后三条判据一起用：真实停顿 →
「那 / 所以 / 但是 / 然后」这类句子起始词 → 120 字硬上限。

**③ 必剪 ASR 那条路没有时间戳。** 导出 srt 时写的是 `0 → 99:59:59` 包住全文的一整块。
不特判的话，阅读页会把一小时的字幕画成一个段落；现在按行拆开，并把时间轴藏掉——
没有时间就不假装有。

### 顺手补的两件小事

- 只读接口 `GET /api/tasks/{id}/transcript`：读已经写在磁盘上的文件，不触发抓取、不改
  任务状态。所以**历史任务也能直接看**，不需要任何数据迁移。
- `.gitignore` 补上 `tasks.db`：`serve` 默认在当前目录建库，在仓库根跑一次就多出一个库
  文件，迟早被 `git add .` 带进仓库。

### 边界

- 不做跳转播放器（时间戳只是让你知道「这句话在第几分钟」）。
- 不做收藏、笔记、多 P 目录、AI 总结。
- 页面是纯静态字符串，无外链无构建，断网也能开；没有鉴权，所以仍然只监听 `127.0.0.1`。

### 测试

326 项（+26）。新增 `tests/test_reader.py` 覆盖解析层与接口层：CRLF、多行正文、坏块、
无序号 srt、占位块拆行、同组格式优先级、路径越界拒绝，以及 404 / 409 / 200 / 空结果四种
响应。

端到端也真跑了：起服务 → 提交一条真实视频 → 轮询到完成 → 阅读页 58 条字幕合成 8 段，
搜索能跳；无字幕、风控、Cookie 失效三种异常各自截图确认过文案。面板那侧用无头浏览器
验过：有产出才出现「阅读 →」，点进去正好是分好段的正文。
