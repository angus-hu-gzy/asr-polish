# 0.15.1

一行代码没改。这一版改的是**说明书写给谁读**，另外堵掉一个凭证泄漏的口子。

## 如果你的「安装」是让 AI 来做

那 `FOR_AI.md` 就是为你准备的。不用翻 README，直接把仓库丢给你的 AI：

> 帮我装一个工具，再把我给的视频做成笔记库。
> 仓库 https://github.com/angus-hu-gzy/asr-polish ，先读根目录的 FOR_AI.md，按它做。
> 每一步动手之前先告诉我你要做什么；不要删我电脑上的文件；
> 装完之后先验收，别急着说完成了。

AI 读不到本地文件的话，让它抓
`https://raw.githubusercontent.com/angus-hu-gzy/asr-polish/main/FOR_AI.md`。

**前提一个，先说清**：你的 AI 得能操作你的电脑（能读写文件、能跑命令）。纯网页聊天窗口
读得到仓库，但装不了 Python、跑不了 `pip`——那种情况 `FOR_AI.md` 里明写了让它停下来直说
做不到，不许编一套步骤让你照着点。听起来很像样、实际什么都没做的教程，比直接说做不到更糟。

## 为什么值得专门写一份给 AI 的文档

因为这两类读者要的东西几乎相反。人要的是「这玩意能干嘛、值不值得试」；AI 要的是
「第一步判断什么、命令是什么、成功长什么样、失败了走哪个分支、哪些事不许碰」。
现在这份 README 给 AI 看，它能学到设计理念，但拼不出可执行的步骤。

`FOR_AI.md` 因此是另一种文体：

- **先判断自己有没有本机权限**，再决定走命令行还是 MCP。第一步不是安装，是自检。
- **终点不定义成「装好了」**，而是 `notes/INDEX.md` + 每条视频一个笔记文件。装完然后呢，
  这个问题不回答，工具就等于没装上。
- **每一步都写「成功长什么样」**。没有验收点，AI 会幻觉式宣布完成——这是这类文档最常见
  的死法，也是这份文档里 6 条 `- [ ]` 存在的唯一理由。
- **危险区单独一节**：不许 `curl | sh`、不许打印或上传 cookie、不许替你去注册充值、
  不许一次抓几百条。最后这条写了理由：那些请求走的是**你自己的账号**，风控记在你身上，
  不记在 AI 身上。没有理由的规则，它守不住。

## 一个顺带的好消息

**走这条路不需要模型 key。** 组织内容的是用户那个 AI，不是 asr-polish；key 只在用网页里的
「总结」按钮时才需要。上一版做完时我担心「别人不会配 key」，这个入口直接绕过去了。

## 修复：cookie 文件名漏网

`.gitignore` 原来按名字逐个列：`cookies.txt` / `*.cookies.txt` / `bilibili_cookies.txt`。
而浏览器 cookie 导出插件最常产出的那个名字是 `www.bilibili.com_cookies.txt`——一个都不匹配，
也正是 README 第二条默认路径里的名字。

后果不是「多一条日志」：谁把导出的文件拷进项目目录方便测试、再 `git add -A`，账号就进了
提交历史，之后删文件也没用，得改写历史才能清掉。

改成 `*cookies.txt` 一条通吃。**别按具体文件名列忽略规则——列不全就是漏一个口子，
而漏的那个往往正好是最常见的名字。**

## sdist 现在带说明书了

之前 `MANIFEST.in` 不存在，setuptools 默认只带 `README.md` 和 `LICENSE`/`NOTICE`。
也就是说：从 PyPI 下载源码包的人**找不到 `FOR_AI.md`**，而它的用处恰恰是「把仓库丢给 AI，
让它照这个装」。装完却读不到，等于没写。

现在包里带了 `FOR_AI.md` / `CHANGELOG.md` / `CONTRIBUTING.md` / `docs/`（每个版本的发布说明）
/ `tools/`（`pre-push` 钩子和 `ci_guard.py`，参与贡献时要用）。

**顺带发现第二处漏网**：`tests/` 里的 `.py` 一直跟着 sdist 走（distutils 默认模板里有
`tests/test*.py`），但 `tests/js/reader_logic.js` 不在默认清单里。把它解包出来跑 pytest，
**51 项全红**——前端纯函数的夹具脚本全在这一个文件里。之前每一版的源码包其实都是这个状态，
只是没人解包跑过测试。现在显式带上，解包后 `473 passed`。

这件事本身就说明了一个道理：文件清单对不对，看 `tar tzf` 数不出来，得**真解包、真跑一遍**。

## 测试

473 项（+14）。新增的这批不是测功能，是**测文档没和代码脱钩**：

- `tests/test_for_ai_doc.py`（9 项）：文档里每条 `asr-polish` 命令都丢给 `cli.build_parser()`
  真解析一遍；`-f` 后面的格式必须存在于 `export.FORMATS`；提到的 MCP 工具名必须在
  `mcp._TOOLS` 里；不许出现 `--limit 0`；不许 `curl | sh`（只扫代码块，正文那句禁令本身不算）。
  以后谁改了子命令名、删了某个参数，这里立刻红，而不是等用户的 AI 照着跑一条报错命令。
- `tests/test_readme.py`（4 项）：README 里列的默认 cookie 路径必须与
  `bili._DEFAULT_COOKIE_PATHS` **完全相等**（不是两边都空就算过）；那句「别转发 cookies.txt」
  不许被「精简」掉。
- `tests/test_cookie_import.py` 新增 `TestCredentialsStayOutOfTheRepo`：不读 `.gitignore`
  猜规则，直接 `git check-ignore` 问三种真实导出文件名。上面那个漏洞没修的话，这条会指出来。

写这份文档的过程中，它抓到我自己三个错：写了不存在的 `--dry-run`；把 `--limit 0` 当
「只看不抓」（它其实是**不限**，照做会把整个 UP 主几百条一次抬走）；让用户把 cookie 粘到
终端（`cookie set` 本来就读剪贴板，让用户往终端粘等于把账号凭据敲进 shell 历史）。
