## 关掉再打开，回到上次读的那一段

```bash
pip install -U asr-polish
```

阅读页多了一件小事。

字幕动辄几万字。一个两小时的分 P 读一半去干别的，回来只能从头翻——原来唯一的定位手段
是搜索，可你要是忘了那句话里的词，就只能一路往下滚。

现在不用了。位置记成「哪一篇 + 该篇第几段」，下次打开同一个任务，先切到那一篇，再滚回
那一段、闪一下，底部浮一句「已回到上次读到的位置（P2）」，旁边一个「回顶部」。九秒后
自己让开，也可以直接关掉。

只存在本机 `localStorage`，按任务 id 分组、按分 P 分开记。切到第二篇读到一半，不会把
第一篇的位置顶掉。

### 三个判断，都是实测逼出来的

**记段号，不记像素。** 像素换个窗口大小就对不上；段号换个屏幕还是同一段。

**「顶部那段」是「header 下方第一条完整的段落」，不是「离界最近」。** 段落带
`scroll-margin-top: 96px`，滚到位之后它停在 96，而界在 69；上一段的下沿在 44，离界
25px，比目标的 27px 还要近。按「离界最近」算会**稳定地差一段**——错误只有一行，但每次
都错，最容易在「大概对了」的错觉里放过。

**只有人真滚过才记。** 页面加载时浏览器自己会发一次 scroll 事件。不设这道闸，第一次
打开就会顺手写下「第 0 段」，于是下次进来白弹一句「已回到上次读到的位置」——位置是对的，
提示是纯噪音。

恢复全程复用搜索那套滚动和闪动，没有第二份滚动逻辑。两份迟早会分叉：一份补了
`scroll-margin` 的偏移，另一份忘了。

### 坏了怎么办

- **段号越界**（任务重跑后字幕变短）：回顶部，不报错。
- **`localStorage` 里是半截 JSON**：当没存过位置处理，不白屏。
- **这两种都不清数据、不弹警告**。位置只是方便，不是数据，不该因为它让页面打不开。

### 没变的

- 抓取、限速、风控退避、任务状态机、`transcript` 接口结构，一行没动。
- 划重点、搜索、播放器、合集目录的现有行为没动。加这个功能之前标的重点还在，导出的
  md 一个字节没变。
- 页面仍是 `reader.py` 生成的单文件 HTML，无框架、无构建步骤、核心零依赖。
- 仍然只监听 `127.0.0.1`，没有账号、不做跨设备同步。

### 测试

380 项（+10）。新逻辑写成纯函数：位置数据的解析（坏 JSON、缺字段、超界）、按篇读写、
`pickCueIndex` 的选段判据。

另有真浏览器验收 34 项：读到第 40 段刷新回同一段、多分 P 先切篇再落段、段号越界、
坏数据、从没读过的任务不多提示也不写位、重点与导出不变。
