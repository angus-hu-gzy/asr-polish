# asr-polish 召回率基准报告

0.5.4 · 2026-11-02 · 语料 196 个 B 站技术视频 / 102.9 万字

---

## 一句话结论

在真实 ASR 字幕上，术语订正**召回 76.7%、精确率 100%**。

拆开看差异极大：**英文/缩写类变体召回 100%，中文两字变体只有 2.3%**。
瓶颈不在窗口调参，而在「两字中文变体天然是同形词」——`酸法` 在腌菜视频里是酸法，
在算法课里才是算法，局部上下文救不回来。

---

## 一、语料：为什么必须是 AI 字幕

| | |
|---|---|
| 来源 | B 站技术类视频（30 个技术关键词搜索结果，824 个候选） |
| 只收 | 字幕轨 `lan == ai-zh`（B 站自动生成 = ASR 产物，天然带错字） |
| 剔除 | 人工上传字幕（文本本身是对的，混进来会把召回算高）、无字幕视频、<3 分钟视频 |
| 多 P 合集 | 取单集时长最接近 20 分钟的那一 P（默认第 1 P 常是几十字的预告） |
| 最终 | **196 篇 / 1,028,628 字**，覆盖词表 87 条中的 **61 条** |

原来估「35 个视频攒 510 万字」不成立：单条 AI 字幕平均只有 5,247 字，35 个视频约 18 万字，
低频变体摊不到统计意义。实际采了 196 个视频才到百万字量级。

采样率：没字幕 77、人工字幕 4、过短 51、其余收下。

## 二、方法：合成扰动 + 回测

在真实字幕里定位**本来就写对的术语**，把术语替换成它的某个变体（模拟 ASR 听错），
再让订正器跑一遍，看能不能改回来：

```
原句   所以时间[复杂度]其实就是 O(n)          ← 语料里本来写对了
扰动   所以时间[复查度]其实就是 O(n)          ← 替换成变体
判定   改回复杂度 = hit / 没改 = miss / 改歪 = wrong
```

四个关键选择：

1. **切片 ±250 字**，向行边界对齐。整篇跑会让多处扰动互相干扰，无法归因到具体变体；
   250 字足够覆盖 ±8 字的上下文窗口。
2. **变体轮转采样**。同一个术语的变体按顺序分配样本，否则 `开园`(36 次) 会主导总体
   召回率，掩盖低频但抓不回来的变体。每术语上限 40 处。
3. **判定看订正列表，不看输出文本**。切片别处可能本来就出现了同一个正确术语
   （左句已经说过 Python），用 `in text` 判断会把漏改误判成命中。
4. **误伤另用干净语料量**。ASR 语料自身就有真错字，在上面数「改动」分不清真改和误改。
   改用 25.9 万字人写对了的口语转写（业绩说明会问答实录等），数同一变体在正常用法里被改坏的次数。

## 四、四个反证实验（说明为什么不能靠调参解决）

**1. 把 medium 全部当 high（放开）**

| | 召回 | 开发集 | 留出集 | 干净语料误伤 |
|---|---|---|---|---|
| 现状 | 76.7% | 104/104 | 97/98 | 0 |
| 全放开 | **100.0%** | **78/104** | **76/98** | **56 处** |

代价不可接受：`我们看一部电影` → `我们看异步电影`，`江湖上的刀客` → `江湖上的Docker`。

**2. 调上下文窗口 / 弱词阈值**

| 窗口 | 弱词阈值 | 召回 |
|---|---|---|
| ±8 | 2（现状） | 76.7% |
| ±25 | 2 | 76.7% |
| ±100 | 2 | 76.7% |
| ±8 | 1 | 78.5% |
| ±25 / ±60 / ±100 | 1 | 78.7% |

窗口从 ±8 放到 ±100 一个点都不动。直接查原因：**medium 样本里只有 2.3% 能在 ±100 字内
找到任何一个上下文词**（不管窗口多大都是 2.3%）——不是窗口太窄，是这些词压根不出现。

弱词阈值 1 能 +1.8pt，且在 259k 干净语料、842 处「本来写对的术语位置」上都测不出代价。
但单元测试当场否掉：`我们讲一部和并发` 被改成「异步」（量词 + 技术词相邻）。**已回退，维持 2**。

**3. 技术词密度判别**

想让「整段是不是技术语境」来决定要不要改，用词表术语共现做判别：

| 阈值 | 能救回的 medium 样本 | 会被误判的用例 |
|---|---|---|
| 1 个 | 19/262 | 26/202 |
| 2 个 | 1/262 | 1/202 |

彻底不成立：词表里是 Python / Docker / SQL 这类**具体专名**，一段讲算法的字幕里
可能一个都不出现。要做得另建一份「通用技术语境词表」（代码/函数/变量/输出/性能…）。

## 五、结论与可选路线

现状是一个**精度优先的合理取舍**，但它意味着产品对外得说清楚：
**能可靠纠正的是英文/缩写类术语，中文术语错写基本纠正不了。**

三条路线，按推荐度排：

**C. 分层输出（推荐）**
medium 变体命中但上下文不足时，不进正文，改为输出「疑似订正清单（待确认）」：
```
已订正 3 处：PASS→Python；色考→SQL；刀客→Docker
另有 2 处疑似（未自动修改，供核对）：酸法→算法？；复查度→复杂度？
```
召回率不变（正文仍然只改有把握的），但用户**能看到**被漏掉的东西。对字幕场景最贴合——
剪映/剪辑软件里逐条确认的成本远低于从头校一遍。

**A. 维持现状**
接受 76.7% / 100%，把定位收窄为「英文技术术语纠错 + 质量体检」。

**D. 建通用技术语境词表**
几百个高频技术用词（代码/函数/变量/运行/输出/性能/报错…），只用于给 medium 变体做领域
门控。能救回一部分，但仍挡不住 `孙子兵法`/`分布式兵法` 这类真同形词，需要配合黑名单。

## 七、0.5.5：文档级主题证据（中文同音错的解法）

上文的四个反证实验说明：**局部上下文这条线索本身不够用**。`酸法`/`算法` 同音，±8 字里
没有任何东西能区分它们；把窗口放到 ±100 也没用，因为上下文词压根不出现。

换一个思路：不看旁边的字，看**整篇在讲什么**。一篇讲算法的字幕里，「算法」出现几十次、
「酸法」只出现一两次——那几次几乎必然是转写错误；反过来讲腌菜的视频里，「算法」一次都
不出现，就不会改。判断依据从「邻字」换成「全篇用词分布」，而这份证据在字幕场景里天然存在，
不需要任何外部语料或模型。

### 判定口径

```
medium 变体在某处成立 ⇔ 局部上下文成立
                      或（正确写法在本篇出现 ≥2 次  且  ≥2 × (变体次数 + 1)）
```

「变体次数 + 1」这一项是必要的：一篇并发讲座里出现「这个兵法书里也有类似思想」，
`兵法` 只出现 1 次、「并发」3 次，(2×2=4) > 3 所以不改；若按「变体次数」算，
2×1=2 < 3 就会被误改。

### 结果（1.03M 字真实 B 站 AI 字幕，1097 处扰动）

| | 0.5.4（仅上下文） | 0.5.5（+文档证据） |
|---|---|---|
| 整体召回 | 76.7% | **93.0%** |
| high 变体 | 100% | 99.5% |
| medium 变体 | 2.3% | **72.1%** |
| 精确率（259k 干净语料） | 100% | **100%** |
| 自然语料新增改动 | — | **103 万字 7 处，全是真错**（`刀客`×3、`多克`×4 → Docker） |

> 注意口径：文档证据要求输入是**整篇文本**（`correct_text(整篇)` / `asr-polish correct 文件`）。
> 基准默认的 ±250 字切片下它几乎不触发（medium 仍是 2.3%），必须加 `--window 0` 才测得出来。
> 传单句时该证据自动失效，行为退化为原判定——这是有意设计，宁可不改。

### 必须配套的三道闸

1. **`ordinary_variants`**：`一部`（量词）、`爱的` 这类本身就是正常词的变体，禁止靠主题翻案，
   只认局部上下文。要不要登记不靠猜：`python tools/audit_variants.py ../corpus_asr --zh-only`
   直接量出每个变体出现在多少篇里（`一部` 37 篇，其余中文变体全部 ≤6 篇）。
2. **搭配保护 `guards`**：`兵法书`/`孙子兵法`/`蒙提派森` 这类固定搭配，即使文档证据成立也不改。
3. **重复键检测**：词表是手写 JSON，`guards` 写两遍时后者会静默覆盖前者——`兵法` 的保护
   第一次就是这样丢的。现在加载时告警。

### 残留风险（说清楚）

- 同形词 + 同篇高频术语：`一部`/`兵法` 之外的变体，若它在某篇里恰好是合法用法且只出现一次，
  主题证据无法区分，会被改。1.29M 字语料里实测的新增改动全部是真错（7 处），但这不等于没有风险：
  构造用例（`这个兵法书里也有类似思想`）确实能触发——只能靠在语料上持续登记
  `ordinary_variants` 与补 `guards` 收敛。
- 阈值越高越安全、召回越低：K=3 时整体召回 88.1%（-1.7pt），K=4/R=3 时 85.5%。当前取 K=2/R=2，
  是在「干净语料 0 误伤 + 自然语料仅 1 处新增」的前提下的选择。
- 真实语料里中文术语错字本身很少（103 万字里可确认的只有 `刀客`/`多克`/`数据及` 这一档，
  个位数）。medium 召回率的提升主要价值在**音频质量差、方言、小模型**的转写上，
  这批语料（B 站 AI 字幕）覆盖不到，需要用同一批音频的 whisper 转写来做下一轮评测。
